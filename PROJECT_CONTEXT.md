# Контекст проекта: Вращающиеся фигуры (мультиплеер)

## Цель проекта
Веб-приложение с интерактивными фигурами: при клике фигура поворачивается в
следующее положение (например, +90°), и это изменение видно в реальном
времени всем удалённо подключённым пользователям.

Это НЕ приложение внутри Miro — отдельный самостоятельный веб-сервис
(изначально рассматривали Miro Web SDK, но решили делать отдельно).

## Формат работы
Образовательный проект — Claude объясняет теорию и пишет код вместе с
пользователем, построчно, с разбором каждой части (а не просто выдаёт
готовый код).

- Python: сильный (numpy/расчёты/графики), но НЕТ опыта с веб-бэкендами
  (лёгкий опыт с FastAPI был давно, почти забыт)
- HTML/CSS/JS: с нуля, не знает вообще
- Инструменты: PyCharm (переустановлен после глюков с Settings — теперь

  и в PowerShell
- ОС: Windows

## Архитектура (согласовано)
```
Браузер (клиент) <--WebSocket--> Python-сервер (FastAPI) <--WebSocket--> Браузер (клиент)
```
Сервер хранит состояние (углы поворота фигур) как единый источник правды.
Клик в браузере -> сообщение по WebSocket серверу -> сервер обновляет
состояние -> рассылает всем подключённым клиентам -> все видят синхронно.

## Как запустить сервер локально
```
.venv\Scripts\activate.bat        (cmd)  ИЛИ  .\.venv\Scripts\Activate.ps1  (PowerShell)
python run.py
```
Сервер стартует на http://127.0.0.1:8000 — уже проверено, работает
(JSON-ответ `{"message":"Сервер работает!"}` виден в браузере).

## Swagger UI (встроенная документация FastAPI)
FastAPI автоматически генерирует интерактивную документацию — ничего
дополнительно ставить не нужно:
- **http://127.0.0.1:8000/docs** — Swagger UI, можно прямо в браузере
  выполнять запросы (кнопка Execute), видеть curl-эквивалент запроса,
  request URL и ответ сервера.
- **http://127.0.0.1:8000/redoc** — ReDoc, альтернативный вид той же
  документации, менее интерактивный.
ВАЖНО: WebSocket-эндпоинты в Swagger UI НЕ отображаются и не тестируются
(показывает только обычные HTTP-маршруты GET/POST/и т.д.) — для будущих
WebSocket-эндпоинтов понадобятся другие способы тестирования. Новые
HTTP-маршруты появляются в /docs автоматически по мере добавления в код.

ЗАМЕЧАНИЕ: на компьютере пользователя есть также старый отдельный проект
`fastAPI_1` (в D:\Programm_for_work\...), у него был маршрут POST
/register — если он тоже запущен и слушает порт 8000, будет путаница/
конфликт портов с нашим текущим сервером. Перед отладкой стоит убедиться,
что запущен именно наш `run.py`, а не старый проект.

## Известные проблемы окружения (решены, держим в памяти на будущее)
- Системный `python`/`py` не работают напрямую — обходим, вызывая venv
  напрямую или указывая полный путь к интерпретатору при создании venv.
- Встроенный SSH в Git for Windows не работает с кириллицей в пути
  пользователя — исправлено через core.sshCommand (см. раздел GitHub).
- В PowerShell нужно активировать venv отдельной командой
  (`.\.venv\Scripts\Activate.ps1`) — активация в cmd на PowerShell не
  переносится, это разные сессии/окна терминала.
- Пользователь иногда печатает текст не в той раскладке клавиатуры
  (кириллица/латиница) — если сообщение выглядит как бессмысленный набор
  русских букв, стоит попробовать декодировать его как английский текст,
  набранный в русской раскладке ЙЦУКЕН.
