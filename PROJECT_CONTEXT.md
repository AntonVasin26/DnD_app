## Цель проекта

Головоломка из нескольких многогранников (треугольники, квадрат,
пятиугольник), у соседних фигур есть ОБЩИЕ вершины (точки) с числами. При
клике фигура физически поворачивается на 1 шаг как жёсткое тело, и числа
в её вершинах циклически сдвигаются — включая общие вершины с соседними
фигурами. Условие "решено" — суммы чисел вдоль заданных линий совпадают с
целевыми значениями. Игра МУЛЬТИПЛЕЕРНАЯ: несколько игроков одновременно
видят одну и ту же головоломку и её состояние в реальном времени через
WebSocket, плюс видят курсоры друг друга (presence).

## Структура проекта

```
app/
  main.py            — FastAPI-приложение, WebSocket-эндпоинт /ws, HTTP /, /api/status
  puzzle_models.py   — модели данных: Point, Shape, Line, Level
  puzzle_engine.py   — PuzzleState: rotate(), is_solved(), scramble() — полностью
                        общие для любого количества точек/фигур (3, 4, 5 вершин)
  puzzle_levels.py   — три готовых уровня ("созвездия"): BUTTERFLY_LEVEL,
                        PENTAGON_LEVEL, SQUARE_LEVEL — единственный источник
                        правды для геометрии, используется и сервером, и тестами
  static/
    index.html       — весь фронтенд: SVG-отрисовка трёх созвездий на одной
                        странице, JS-логика вращения/анимации/WebSocket,
                        presence-курсоры других игроков
    background.jpg, floor.webp, Tiles_Roughness.jpg — текстуры фона

test_engine_butterfly.py  — ручной тест уровня "Бабочка"
test_engine_pentagon.py   — ручной тест уровня "Скорпион" (пятиугольник)
test_engine_square.py     — ручной тест уровня "Телец" (квадрат)
run.py               — точка входа для локального запуска
requirements.txt      — fastapi==0.115.0, uvicorn[standard]==0.32.0
PROJECT_CONTEXT.md    — этот файл
```

Технический стек: FastAPI + vanilla JS/SVG на фронтенде, без сборки
(build step), WebSocket как единственный источник правды о состоянии
(authoritative server state — сервер решает, клиент только отображает).

## Архитектура бэкенда (актуально на сейчас)

`LEVELS` — словарь `level_id -> Level` (`"butterfly"`, `"pentagon"`,
`"square"`), полностью общий: добавление нового уровня требует только
добавить объект `Level` в `puzzle_levels.py` и в этот словарь — никакого
изменения движка не требуется (проверено на практике трижды).

`puzzle_states: dict[str, PuzzleState]` — по одному независимому игровому
состоянию на каждый уровень; все уровни живут ОДНОВРЕМЕННО на одной
странице (не выбор одного уровня из списка).

`busy_until: dict[str, float]` — блокировка анимации ОТДЕЛЬНО на каждый
уровень (`ANIMATION_LOCK_SECONDS = 2.1`, должно совпадать с длительностью
анимации на фронтенде: `FADE_DURATION_MS*2 + ROTATE_DURATION_MS =
250+250+1600`), чтобы повороты одной и той же фигуры не накладывались друг
на друга, но при этом разные уровни не мешают друг другу.

`ConnectionManager` — держит список активных WebSocket-соединений и
per-connection "личность" игрока (`id` + цвет из `PLAYER_COLORS`, список из
6 цветов, выдаются по кругу без повторов среди активных). Нужно для
presence: курсоры других игроков на экране.

Протокол WebSocket (`/ws`), сообщения:
- `welcome` — разово новому клиенту: его `id` и `color`.
- `state` — снимок состояния ОДНОГО уровня (`level_id`, `values`,
  `is_solved`, `lines` со значением/целью/флагом `ok` для каждой линии,
  `shapes`, `last_move` — `None` для снимка при подключении, либо
  `{shape_id, direction}` после чьего-то реального поворота, чтобы все
  клиенты проиграли анимацию именно у себя).
- `cursor` — позиция курсора игрока (пересылается всем кроме отправителя,
  с добавленным `id`/`color`/`level_id`).
- `cursor_leave` — игрок отключился, остальные убирают его курсор.

При старте сервера каждый уровень перемешивается (`scramble()`) от
изначально решённого состояния — с подстраховкой "прокрутить ещё раз",
если перемешивание случайно вернуло уровень в решённое состояние.

## Уровни ("созвездия")

Названы "созвездиями" по просьбе пользователя (не "уровень 1/2/3", а
конкретные названия) — id уровней (`butterfly`/`pentagon`/`square`)
остаются техническими и НЕ меняются, меняется только `name`.

### Созвездие Бабочки (`butterfly`) — первый, самый простой

Два треугольника, соединённые ОДНОЙ общей вершиной C (`left=[A,C,D]`,
`right=[B,E,C]`). Диагонали идут ЧЕРЕЗ общую вершину: `diag1=[A,C,E]`
(target=9), `diag2=[B,C,D]` (target=9).

### Созвездие Скорпиона (`pentagon`) — второй уровень

Пятиугольник `A-B-C-D-E` + два треугольника, приклеенных РЁБРАМИ (не
вершинами) к сторонам 1 (A-B) и 3 (C-D): `top_wedge=[A,B,F]`,
`bottom_wedge=[C,D,G]`. У треугольников ПО ДВЕ общие точки с пятиугольником
(сама грань) — более тесная связь, чем у бабочки. Линии: `line1=[F,B,C,G]`
(target=18), `line2=[F,A,E]` (target=12), `line3=[G,D,E]` (target=16).
Точка E участвует сразу в line2 и line3.

### Созвездие Тельца (`square`) — третий уровень

Квадрат `A-B-C-D` (единственная 4-точечная фигура в проекте, поворот на
90° — движок и фронтенд полностью общие, специального кода не
потребовалось) + два треугольника, приклеенных ВЕРШИНАМИ (как у бабочки, а
не гранями, как у скорпиона): `wedge_left=[A,F,E]` касается квадрата
только в вершине A, `wedge_right=[B,E,G]` — только в вершине B; сами
треугольники соединены общей вершиной E (аналог точки C у бабочки). Линии
(по просьбе пользователя, сознательно ТОЛЬКО ДВЕ, в отличие от других
уровней): `line1=[F,A,D]` (target=11), `line2=[G,B,C]` (target=12). Точка
E сознательно НЕ входит ни в одну линию — она всё равно двигается при
повороте треугольников, но её значение не проверяется условием суммы.

Порядок точек в `point_ids` каждой фигуры должен совпадать с реальным
обходом вершин на экране по часовой стрелке (в системе координат SVG,
y вниз) — это направление, в котором положительный угол CSS `rotate()`
поворачивает фигуру. Для уровня "Телец" правильность обхода была проверена
через знак 2D-векторного произведения (`wedge_right` должен быть
`[B, E, G]`, а не `[B, G, E]`).

Решаемость всех трёх уровней подтверждена BFS-обходом полного графа
достижимых состояний (все комбинации `(shape_id, direction)`): для
уровня "Телец" — 5040 всего достижимых состояний, 30 случайных
перемешиваний проверено, 0 нерешаемых, от 0 до 7 ходов до решения.

## Фронтенд (`app/static/index.html`)

Все три созвездия — на одной странице одновременно (не выбор одного
уровня из списка), каждое в своей `<section>` со своим `<svg
id="puzzle-svg-{levelId}">`. Фабрика `createPuzzleView(levelId)` создаёт
объект представления для каждого уровня, хранится в `puzzleViews`.
`LEVEL_SHAPE_CENTROIDS` — координаты центра поворота для каждой фигуры
каждого уровня. `stepDegrees = 360 / pointIds.length` — угол поворота за
один шаг (120° у треугольников, 90° у квадрата, 72° у пятиугольника),
полностью обобщено, никакого спецкода под конкретные углы.

Поля (отступы) вокруг фигур на уровнях "Скорпион" и "Телец" были расширены
по просьбе пользователя (были слишком тесными) — изменены только
`viewBox`/размеры контейнера `<svg>`, координаты самих точек не менялись:
- Скорпион: `viewBox="200 -20 480 640"` → `viewBox="150 -50 560 730"`
  (контейнер 480×640 → 560×730), итоговые поля: слева 72.6, справа 118.9,
  сверху 88.2, снизу 67.9.
- Телец: `viewBox="190 90 480 520"` → `viewBox="150 50 560 600"`
  (контейнер 480×520 → 560×600), итоговые поля: слева/справа 87.8,
  сверху 100.0, снизу 90.0.

Заголовки на странице: `<h1>` — "...все созвездия на одной странице";
`<h2>` уровней — просто "Созвездие Бабочки" / "Созвездие Скорпиона" /
"Созвездие Тельца" (без слова "уровень").

## Развёртывание: собственный VPS (реализовано)

Пользователь развернул сервер на собственном арендованном VPS (Ubuntu
24.04, IP `153.80.245.222`), чтобы игроки подключались напрямую, без
туннелей и без домашнего компьютера пользователя в цепочке (что было
важно, так как на домашнем компьютере активен VPN (AmneziaVPN), который
сильно ухудшал качество соединения через любые туннели — cloudflared
quick tunnel и playit.gg были опробованы раньше и отброшены: у cloudflared
была плохая связь из-за VPN, у playit.gg TCP-туннели (нужны для
WebSocket) оказались платной функцией).

Что сделано на сервере:
- Установлен `python3`, `python3-venv`, `python3-pip` (`apt install`).
- Код скопирован через `scp` НАПРЯМУЮ (не через git — упрощённый разовый
  деплой): только `app/`, `requirements.txt`, `run.py` в `~/puzzle-app`
  на сервере (без `.venv`, `.git`, `.idea` — они не нужны на сервере и
  только зря тратят время передачи).
- Создано виртуальное окружение `~/puzzle-app/venv`, установлены
  зависимости из `requirements.txt`.
- Сервер запускается как systemd-служба `puzzle` (файл
  `/etc/systemd/system/puzzle.service`), чтобы работать постоянно и
  переживать разрыв SSH-сессии и перезагрузку сервера:
  ```
  [Unit]
  Description=Puzzle App
  After=network.target

  [Service]
  WorkingDirectory=/root/puzzle-app
  ExecStart=/root/puzzle-app/venv/bin/python3 -m uvicorn app.main:app --host 0.0.0.0 --port 8000
  Restart=always

  [Install]
  WantedBy=multi-user.target
  ```
  Включена и запущена через `systemctl daemon-reload / enable / start
  puzzle`.
- Порт 8000 открыт (`ufw allow 8000`) — предварительно проверено, что он
  не входит в список глобально заблокированных портов хостинга.
- Ссылка для игроков: `http://153.80.245.222:8000`.

**Важно на будущее:** это разовый деплой копированием файлов, НЕ через
git — значит, при следующих изменениях кода их нужно будет заново
скопировать на сервер (`scp`) и перезапустить службу
(`systemctl restart puzzle`), это ещё не автоматизировано.

**Безопасность:** пароль root от VPS один раз случайно попал в переписку
с Claude (пользователь вставил его не в то окно). Рекомендовано сменить
пароль через `passwd` на сервере — **нужно проверить, было ли это
сделано**.
